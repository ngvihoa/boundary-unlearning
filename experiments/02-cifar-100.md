# Thí nghiệm 02 — Phase 1: Phương pháp gốc trên CIFAR-100

## Mục tiêu và trạng thái

Đánh giá Boundary Shrink và Boundary Expanding theo code tác giả khi chuyển sang
CIFAR-100: mức quên lớp beaver, khả năng giữ 99 lớp còn lại và chi phí so với
Retrain. Đây là chuyển quy trình sang dataset 100 lớp, không tuyên bố tái lập toàn
bộ paper. Distance weighting, retain KL, BN freeze và tuning thuộc [Phase 2](03-distance-weighted-variants.md).

- [Notebook Phase 1](boundary-unlearning-cifar-100-experiment.ipynb).
- [Notebook Phase 2](boundary-unlearning-cifar-100-phase2.ipynb).
- Dataset: `alincijov/cifar-100`, đọc pickle `train`, `test`, `meta`, dùng fine labels.
- Đã có kết quả Kaggle từ flow kết hợp cũ và các ablation do người dùng cung cấp.
  Notebook `_v2.ipynb` chứa kết quả cũ được giữ làm tham chiếu.
- Flow tách phase mới được kiểm tra CPU bằng dữ liệu nhỏ, gồm ZIP và khôi phục
  model trong phiên mới. **Chưa chạy lại đầy đủ Phase 1 mới trên Kaggle.**

## Dữ liệu và đối chứng

Quên **`FORGET_CLASS = 4`, `beaver` (hải ly)**. Tên và thứ tự lớp lấy từ `meta`.

| Tập | Tất cả | Forget | Retain: 99 lớp |
| --- | ---: | ---: | ---: |
| Train | 50.000 | 500 | 49.500 |
| Test chính thức | 10.000 | 100 | 9.900 |

Không tách validation từ train. Test có nhãn được dùng để đánh giá và chọn
checkpoint như flow hiện tại. Khi báo cáo cần nêu rõ chính sách này.

| Model | Cách tạo |
| --- | --- |
| Original | Train đủ 100 lớp |
| Retrain | Train từ đầu trên retain set, classifier vẫn có 100 đầu ra |
| Boundary Shrink | Khởi tạo từ Original, fixed-bound FGSM pseudo-label, CE trên ảnh forget sạch |
| Boundary Expanding | Khởi tạo từ Original, mở 100 → 101 đầu ra, học nhãn phụ rồi prune còn 100 |

Bảng cuối có **đúng 4 model**. Shrink thuần dùng `EXTRA_EXP=None` và
`bn_stats_mode="update"`; không có BN freeze hay distance/KL trong Phase 1.

## Cấu hình

| Tham số | Giá trị mặc định |
| --- | --- |
| Profile / seed | `paper` / `2022` |
| Model | AllCNN, 3 kênh, 100 lớp, filters_percentage=0.5, BatchNorm, không dropout |
| Train Original/Retrain | 30 epoch/model, SGD, LR 0.1, momentum 0.9 |
| Unlearning | 10 epoch/phương pháp, SGD, LR 1e-5, momentum 0.9 |
| Batch size / workers | 64 / 2 |
| FGSM bound | 0.1, không random start |
| Input và attack normalization | `matched`, mean/std (0.5, 0.5, 0.5) |
| Tái sử dụng checkpoint | `False`, chạy lại baseline trong phiên Phase 1 mới |

Epoch/LR không đổi so với cấu hình CIFAR-100 trước khi tách phase.
Một phương pháp unlearning có `10 × ceil(500/64) = 80` update, khác CIFAR-10
(790 update). CIFAR-10 vẫn giữ attack `repo_exact`; cần nêu các khác biệt này
khi so sánh hai dataset.

## Chạy và đóng gói Phase 1

1. Commit/push code mới và import notebook Phase 1 vào Kaggle.
2. Gắn CIFAR-100, bật GPU/Internet, chạy trong phiên mới. Mặc định train lại
   Original/Retrain; đây là lần chạy baseline mới, không phải cập nhật code nhỏ.
3. Chạy Shrink và Expanding, rồi evaluation. Bảng có train retain/forget,
   test all/retain/forget, training/unlearning time và FGSM crossing rate khi có.
4. Chạy các cell hình cần dùng; t-SNE có thể bỏ qua. Visualization chỉ dùng 4 model.
5. Chạy cell export cuối và tải `/kaggle/working/result.zip`.

Run tag: `cifar100_phase1_paper_forget4_<hash>`. Các output cũ khác run tag được giữ;
nên dùng phiên mới để archive của lần chạy này dễ kiểm tra.

```text
result/
├── checkpoints/                    # Checkpoint train tốt nhất, unlearning và widened
├── figures/<run_tag>/              # PNG/PDF/JSON/NPZ nếu chạy visualization
├── <run_tag>_metrics.csv / _config.json / _results.html / _unlearning_details.html
└── phase1/<run_tag>/
    ├── phase1_manifest.json
    ├── config.json / rows.json / metrics.csv / results.html
    └── checkpoints/
        ├── original_evaluated.pt
        ├── retrain_evaluated.pt
        ├── boundary_shrink_evaluated.pt
        └── boundary_expanding_evaluated.pt
```

Evaluation lưu ngay snapshot **đúng model trong bộ nhớ đã được đánh giá** vào
bundle, gồm trọng số và BN buffers. Code train vẫn lưu checkpoint tốt nhất theo
test accuracy, còn model trả về khi train mới là model cuối epoch. Bundle giữ
đúng model dùng trong bảng, không âm thầm đổi sang checkpoint tốt nhất.
Nếu bật reuse, snapshot cũng ghi đúng model đã nạp và được đánh giá.

Manifest ghi phiên bản định dạng, run tag và SHA-256 của checkpoint/config/kết quả.
Config ghi code commit, phiên bản Python/Torch/torchvision/NumPy, kiến trúc, mapping
lớp, chuẩn hóa, cấu hình và fingerprint ordered pixels/fine labels của train/test.
ZIP nằm ngoài `result/`. Chạy lại riêng export chỉ đóng gói các file đang có;
không train, đánh giá hay snapshot lại từ model có thể đã bị thay đổi.

## Sang Phase 2

Giữ bản ZIP đã tải. Gắn Output đã lưu của Phase 1 vào notebook Phase 2, hoặc upload
ZIP thành Kaggle Dataset và Add Input; đồng thời gắn dataset CIFAR-100 gốc.
`PHASE1_SOURCE=None` tự tìm một bundle; có thể chỉ định đường dẫn ZIP, thư mục
chứa một manifest hoặc file `phase1_manifest.json` cụ thể nếu có nhiều gói.

Loader kiểm tra hash/kiến trúc, khôi phục AllCNN và Expanding dạng Sequential đã
prune, kiểm tra pixels/labels, mapping và normalization trước khi thử biến thể.
Không có cell hoặc fallback train lại 4 baseline trong Phase 2. Snapshot là
state_dict để khởi tạo optimizer mới, không phải trạng thái tiếp tục optimizer cũ.
